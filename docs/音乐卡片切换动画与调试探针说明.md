# 音乐卡片切换动画与调试探针说明

本文件记录 2026-09-29 ~ 09-30 这一轮对「音乐胶囊岛 ↔ 音乐卡片」切换路径的修改、原因与验证方式。

## 1. 修改了什么

### 1.1 去掉「第二个形变直接拒绝」的拦截（MiniPlayerRuntime.kt，prepareGroupUnsafe）

- 改动：删掉
  `if (morph != null || group != null) { trace("group refused: ..."); return null }`。
- 原因：快速连点音乐胶囊岛时，第二次切换请求会被这条拦截拒掉，转场退化成「原地切换」，
  看起来就是卡片从行下面直接冒出来，而不是从胶囊岛弹出去。
  上游（zyl6932/HyperMusicCover）没有这条拦截：正在跑的形变由 `MiniCardMorph.aim()` 掉头，
  从当前位置继续弹。去掉后快速连点是「弹出去 → 中途掉头 → 弹回来」。
- 影响范围：只影响音乐岛到卡片的形变；通知岛的形变路径未改动。

### 1.2 新增两个只读调试探针（MiniPlayerRuntime.kt + Main.java）

设备上 logd 不保留 INFO 级日志，模块日志读不到；而原有的 `op mini` 一次返回约 250KB，
刚好把末尾（逐帧轨迹）截掉，没法跟动画。因此新增：

- `op trace`（`--es grep <x>`、`--ei n <行数>`）：读模块内存里的逐帧轨迹环
  （landing 环 + scene 环），可过滤、可截断，用于逐帧定位动画异常。
- `op geo`：读当前各岛的绘制框（胶囊岛 pill / 小岛 small / 卡片 card / 切换中的移动体 mover
  + 它们的方向与进度），一行短文本，可 40ms 轮询，用于量化动画轨迹。

两个探针都是**只读**的，不参与任何动画或状态机，仅在收到对应广播时读取并回传文本。

### 1.3 做过但已回退的实验（不留痕，仅记录）

为对齐「卡片原地放大 / 胶囊岛原地淡出」的观感，尝试过以下改动，均因副作用回退：

- 把音乐形变的「行端」改成卡片自己的框（`cardGrowthBox`）：收尾时胶囊岛被留在原地不回位。
- 给卡片加 0.28×卡片高度的向上偏置（`CARD_GROW_RISE`）：同一问题加剧。
- 在 `moverDy()` 里对音乐钳制垂直偏移：会让卡片落点算到布局位置（屏幕顶），导致卡片抬高。
- 对 `noteStandInChanged()` 加 200ms 防抖：`Main.onMiniStandInChanged()` 同时驱动封面层
  与通知行的显示，跳过它会让背景不显示、通知状态错位。

最终代码保留上游的形变与偏移算法，只保留 1.1 与 1.2。

## 2. 怎么验证

```bash
# 逐帧轨迹（最近 40 行，含 pill/small/mover 的框与进度）
adb shell "am broadcast -a com.os4.musiccover.PROBE --es op geo"

# 轨迹环，过滤关键字（如 group refused / pile / switch）
adb shell "am broadcast -a com.os4.musiccover.PROBE --es op trace --es grep switch --ei n 40"
```

验收口径：快速连点音乐胶囊岛时，
① 音乐这一侧只在「行(约 y=2409) ↔ 卡片自己的位置」之间移动，不越过行以下、也不越过卡片位以上；
② 行里的胶囊岛（pill）全程在原位 `274,2409 673x156`，转场结束后仍回原位；
③ 通知堆岛的反向移动与改动前一致。

## 3. 影响范围

- 仅涉及音乐岛 ↔ 音乐卡片这一条形变路径与两个调试探针。
- 通知岛、锁屏列表、封面/歌词、时钟等路径未做逻辑改动。
