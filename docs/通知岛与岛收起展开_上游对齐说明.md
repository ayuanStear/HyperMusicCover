# 通知岛与「岛」收起展开：与上游对齐说明

## 这一轮做了什么

把**通知岛的逻辑**和**岛的收起 / 展开手势逻辑**统一换成上游
[zyl6932/HyperMusicCover](https://github.com/zyl6932/HyperMusicCover)（`main`，2026-09-29 的
`f674da1`）里对应的实现，并清掉测试期间留下的探针代码。不改动别的功能（封面 / 壁纸、时钟、
锁屏歌词、息屏、设置页、尺寸滑块、音乐卡片与胶囊之间的形变都保持原样）。

涉及文件：

| 文件 | 改了什么 |
| --- | --- |
| `LockIslands.kt` | 合计岛的文案与图片、隐藏内容的条数、焦点通知文字里的标记 |
| `MiniPlayerRuntime.kt` | 通知行下拉收起的判定与落位、按下时「这一拉是谁的」的判定 |
| `MiniPlayerView.kt` | 行文字按字比较、空行不占位（一行岛居中） |
| `MiniCardMorph.kt` | 胶囊与卡片交接文字时的安全处理（上游 #11） |
| `Main.java` | 卡片 / 通知行那次下拉派发到收起（去掉本地启发式） |

## 逐项对照

### 1. 合计岛的文案与图片（`LockIslands.aggregate` / `stackText`）

- 上游：`Note(STACK_KEY, lead.pkg, lead.title, stackText(lead, n), lead.icon, time = lead.time, …)`
  —— 标题是领头那条的标题，内容多于一条时前面加「N 条通知 ·」，图片用领头那条的。
- 本分支原来的做法：文案固定成「通知 / N 条通知」，图片另外挑「时间最新」的那条。
- 现在按上游来。内容被隐藏（锁屏只显示 SystemUI 的 `notification_hidden_text`）时不再拼成
  「3 条通知 · 你有一条新消息」，而是整行就是条数：一条显示那句占位，两到五条
  「你有两条新消息」……五条以上「你有多条新消息」。这条规则本身也是上游的
  （`1b706bf`）。

### 2. 焦点通知文字里的标记（`LockIslands.html`，上游 `498cab9`）

MIUI 的焦点协议会把 `<font color='#0FAD50'>…</font>` 这样的标记写进文字，插件那一行是过
`Html.fromHtml` 画的，所以岛上也得按标记读；`Template` 的 title / text 改成 `CharSequence`
带样式传给行，普通通知自己的标题和内容不过这一道（SystemUI 不解析它们）。

### 3. 通知行下拉收起：不再由本地启发式拦截（`Main.cardSwipe` / `MiniPlayerRuntime`）

- 原来的做法：按下时记住手指下面那条行的屏幕位置，下拉过阈值后看它有没有跟着手指走，判断
  「这一拉是列表的还是通知岛的」；是列表的就交给列表、先把第一条滚回来，否则才收岛。为此还
  读了 `NotificationStackScrollLayout.mOwnScrollY` / `mBackwardScrollable`。
- 上游：没有这套判定 —— 通知行上的一次下拉就是这条通知自己的，`collapseRow` 跟着手指把这一
  堆收进岛，拉得不够 / 放手太早由形变自己弹回原位。
- 现在按上游来：本地那套判定（`pullKeepsForList`、`listScrolledAway`、`pullRowMoved`、
  `stackCanScrollUp`、`stackScrollPx`、`listScrollWhy`）整段删掉，`Main.cardSwipe` 里对应
  的分支也去掉。

### 4. 收起落位（`MiniPlayerRuntime.collapseRow` 的 `flightHome`）

- 上游：**从哪出来回哪去** —— 原来在胶囊里的回胶囊，原来在小圆岛里的回小圆岛；更早就是卡片
  的音乐岛（不是被拉出来的）也回胶囊里。
- 本分支上一版用的是另一条规则（只要音乐胶囊在行里，通知统一落到右边的小圆岛）。
- 现在按上游来。

### 5. 收起的形变被打断

`releasedRowAt` 里「正在收起就不认这一行」的早退去掉了（上游没有）：收起过程中手指落在通知
行上再下拉，事件由模块接住（`collapseRow` 自己会拒绝第二次形变），不会再被原生列表拿去滚动 /
选中那条通知，正在跑的动画因此可以继续跑完。

### 6. 行文字与空行（`MiniPlayerView`，上游 `498cab9` / `800da8f`）

- 标题 / 副标题按**字**比较（`TextUtils.equals`），带样式的文字不会每一帧被重设一遍。
- 没有字的那一行 `GONE`，只剩一行时由列自己居中（录音机那种只有计时器的焦点通知原来读起来
  偏上）。

### 7. 形变交接文字时的安全处理（`MiniCardMorph`，上游 `4f756e2`）

胶囊与卡片交接时，原来把卡片 `TextView.text`（按卡片量好的 `PrecomputedText`）直接 setText
到行上，度量不同会抛 `IllegalArgumentException`，而且是在帧回调里抛，会把 SystemUI 带崩
（上游 #11）。现在复制成 `SpannedString` / 字符串再设，仍然拒绝就只记一次日志、这一行保留
自己的文字。

## 保留的本分支改动（不在这次替换范围内）

- 通知「不合并」开关（`op notifmerge` / `LockIslands.unmergeNotifications` 与它的管线钩子）。
- 按锁屏「通知显示方式」决定是否展开成列表（`LockIslands.currentDisplayState` /
  `MiniPlayerRuntime.showStackAsList`）。
- 模块拿到 Context 之后重读通知（名称与图标不再退成包名 / 空图，`onContextReady`、图标兜底）。
- 收起过程中防止形变停在半路的兜底（`pileWatch` / `endPile` 的收尾判定）与
  `noteDragEnd` 里「过了阈值就直接收」这一条。
- 音乐卡片 / 封面 / 时钟 / 歌词 / 息屏 / 设置页等与本主题无关的部分。
